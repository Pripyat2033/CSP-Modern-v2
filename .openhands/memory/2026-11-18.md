## GRAPHITE TEMPERATURE LINK WIRED (commit e097ad0)

The pending next step: `graphiteTempC` was computed in `UnifiedReactorCore` but never
fed to the neutronics; the retired point-kinetics `ReactivityModel` carried the wrong
(negative) sign. Both now fixed.

**The measurement.** `openmc/rbmk_graphite_mgxs.py` sweeps graphite T 600->800 K and
reports the fractional change of each homogenised 2-group constant per kelvin. Net
cell coefficient **+1.17e-5 /degC, POSITIVE** (the RBMK trait). The effect is thermal
scattering: ss21 (+4.9e-3/K) and sr1 (+2.9e-4/K) grow as graphite heats. Output
`openmc/openmc_graphite_mgxs.json`.

**Why 600-800 K, not the 873 K operating point.** The S(alpha,beta) tables top out at
800 K (`c_H_in_H2O` and `c_Graphite` both). Measuring at 873 K needs OpenMC temperature
*interpolation* (`settings.temperature = {"method":"interpolation"}`), which works for
the free-gas XS but NOT for the thermal law (raises "does not bound 873 K"). So the
slope is a 600-800 K chord, and the Java scaling factor is *anchored* at the core's
nominal graphite temperature (600 degC = 873.15 K) so the correction is a perturbation
about nominal (factor = 1 there -> seed-critical preserved). Honest caveat recorded in
the resource note: the ss21/ss12 slopes are nonlinear, so this overestimates at 873 K.

**THE MATCHED-PAIR FINDING (important).** The slopes are *fractional* changes of the
OpenMC cell's constants, so they are valid ONLY against the OpenMC-derived lattice
table. Against the shipped 1-D table (whose sr1/ss21 differ ~9-360x) the whole-core
effect flips NEGATIVE (-2.4e-5/degC). Fix: `RbmkGraphiteTemp.matchesLattice()` gates
the link on `LatticeTable.source().startsWith("openmc")`. It is a no-op with the 1-D
table. **Consequence: the graphite link and the pending OpenMC-table shipment (Step 1b)
are a matched pair — ship them together or the link is inert.**

## RBMK COMPLETENESS AUDIT — the radial-flux TILT bug (commit 59bc0e7)

Ben's gut ("the RBMK is simulated wrong") produced one CONCRETE, reproducible bug,
found by probing the LIVE core (2000 steps) and reading the flux field directly.

**Symptom.** The live 3D fast flux is tilted ~12x to one side in a geometrically
SYMMETRIC core: `L/R = 12.75` (phi(x)/phi(-x) reaches 0.012 at x=22), mirror-x error
= 1.20 of the total. It is NOT a probe artifact (confirmed by direct mirror-pair
readout on `RbmkSolver3D.phi1`). It is stable/growing, not convergence noise.

**Root cause.** `RbmkLattice.channels()` step 2 fits the control count to exactly
211. The pitch-3 base set is 213 cells; the code dropped cells ONE AT A TIME by
descending radius. At r=24.19 there is a tie, and it removed BOTH x=-24 rods,
leaving the x=+24 rods unmatched. A one-sided absorber pattern against the
reflective radial BC excites a near-degenerate tilt mode, so the power iteration
settles on a tilted flux. (Decisive test: mirroring those 2 rods drops L/R
17.3 -> 1.2.)

**Fix.** Drop whole SYMMETRY ORBITS (a cell with its x/z mirrors), never one cell.
The 2-cell on-axis pair {(-24,0),(24,0)} fits 213->211. Result: control is now
**211/211 mirror-symmetric** (was 209/211); live-core tilt falls to **L/R=1.24**,
mirror error **0.148** (8x better). `RbmkGeometrySelfTest` gained a check that
FAILS on any unpaired control rod (32 checks now). All 12+ physics self-tests still
pass (RbmkGeometry 32, RbmkPhysics 15, RbmkSpatial 18, Solver3DStability 35,
SolverMG 10, UnifiedReactorCore 6, ExperimentVariants 6, AccidentSequence all PASS).

**Residual (NOT a bug, documented as named-only `kinetics.spatial_instability`).**
A slow tilt remains (L/R 1.24 -> 1.79 over 60k steps). It is genuine physics for a
2100-cell core with weak radial coupling + a perfectly reflective outer BC (no
radial leakage). It is also why `SpatialReactorCoreSelfTest` still shows its KNOWN
PRE-EXISTING FAILURE (scram fission 0.27 not <0.5). Three unpaired FUEL cells also
remain, from the fuel-count cap (region 1885 cells vs 1872 channels = 13 unused,
an odd number, so perfect symmetry is unreachable with the placeholder circle).
