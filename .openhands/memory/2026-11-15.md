## THE ROSFOND ROOT CAUSE (the discovery)
ROSFOND neutron files are in the RESOLVED/UNRESOLVED-RESONANCE representation.
Their MF=3 pointwise XS is **ZERO below the resonance range** — U-235 MF=3 MT=1 is
0.0 b at 0.0253 eV (real value 585 b), first nonzero at 2.25 keV. Every thermal /
epithermal resonance lives in MF=2. Read straight in, you get a moderator-only
cell (k_inf ~0.03, fission ~1e-4). NOT a code bug — it is what the file contains.
Fix: standard reconstruction, NJOY RECONR->BROADR via
`openmc.data.IncidentNeutron.from_njoy`, written to the same per-nuclide JSON
cache the pipeline already reads (`tools/lattice/reconstruct_rosfond.py`), so
rbmk_cell.py / rbmk_spectrum.py / emit_constants.py run unchanged.
Supporting fixes: natural carbon (ROSFOND ships graphite as ONE ZA-6000 eval that
already has C-12+C-13; its separate C-13 file has no elastic, so the isotopic
split can't be built from ROSFOND — take natural carbon where present, else the
split, chosen by which files exist, not by source name); metastable isomers
(Nb-93M and Nb-93 share ZA 41093, file name marks the isomer with 'M' after the
mass — prefer the ground state); ENDF-6 floats with a space in the exponent
('2.60560+ 4').

## ROSFOND DATA-PATH FIX — solved and proven (commit daaed39)

Ben's question: "can you fix the ROSFOND issue using NJOY? this is a lot of work."

**Answer: yes, and it is now fixed and RUN end-to-end — not just described.**

### The bug (root cause, confirmed by inspection)
ROSFOND neutron files are in the **resonance representation (MF=2)**. Their MF=3
pointwise cross sections are **ZERO below the resonance range**. Proven on a real
ENDF/B-VIII.0 Pu-241 file: the raw MF=3/MT18 section has 108 points and the value
at 0.0253 eV is exactly **0.00 b**. Reading it straight gives a moderator-only
cell → k_inf ~0.03. Not a code bug; the file simply does not carry thermal
pointwise values.

### The fix
`tools/lattice/reconstruct_rosfond.py` was rewritten to drive **NJOY directly**
(RECONR -> BROADR) with a hand-written deck, then parse the PENDF with the
lattice's OWN `endf6.py` reader. The earlier cut called
`openmc.data.IncidentNeutron.from_njoy` — which could never run here because
**OpenMC is not on PyPI** (pip: "No matching distribution"). NJOY IS installable:
`pip install njoy==2016.78` ships a real 4.8 MB ELF binary at
`~/.local/lib/python3.13/site-packages/njoy/bin/njoy` (the `njoy` on PATH is a
Python wrapper that pipes the deck to it). So the whole path now needs only
`pip install njoy` — no conda, no OpenMC.

### Proof (real files, not synthetic)
- U-235 (ENDF/B-VIII.0, 36 MB from the NJOY test resources): reconstructed
  fission **586.6 b** @0.0253 eV (repo `verify.py` target 585 ±10) and capture
  **99.4 b** (target 99 ±4). Both inside tolerance.
- Pu-241: fission 1012 b, capture 363 b; 18,430 points, 1e-5 eV -> 20 MeV.
- `test_reconstruct_rosfond.py`: 7/7 (MAT reader skips the `$Rev::` header; the
  resonance-trap guard flags zero-at-thermal and passes nonzero).
- All lattice python tests still green: sources 9/9, endf6 11/11,
  import_rosfond 8/8, reconstruct 7/7.

### The guard (so this cannot silently recur)
`fetch_rosfond.py` now REFUSES to cache a fission/capture section that is exactly
zero at thermal energy and prints "reconstruct it with reconstruct_rosfond.py
before converting. Skipping, not faking." On the raw Pu-241 file it writes only
MT 1/2/4/16; on the reconstructed one it writes all six.

### NJOY deck gotchas (cost real time)
1. **MAT must be read from a real 80-column record, not the `$Rev::` header.**
   ROSFOND files open with `$Rev:: 1451 ... $Date::` which is <80 cols; a naive
   column-66 slice read a bogus MAT (`1`), and **NJOY then hung forever on stdin**
   (it read a card that was never coming). Fixed `_first_mat()` to require
   MAT+MF+MT all numeric with sane ranges.
2. RECONR card 2 is `mat ncards ngrid`; `ncards=2` = the two descriptive lines.
   `9443 2/` works; `9443/` and `9443 1/` FAIL ("Bad integer for item 1").
3. BROADR reads the PENDF on **tape 20+21 and writes tape 22**; tape22 must be
   pre-created (touch) or it errors "Cannot open file 'tape22'".
