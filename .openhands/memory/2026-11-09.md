## Fabric 1.20.1 gotcha that cost time
`ResourceManager.findResources(prefix, predicate)` — the `prefix` argument is a
DIRECTORY-style match. `findResources("opb82_rules", p -> p.getPath().endsWith(".json"))`
returns NOTHING for a file at `data/csp/opb82_rules.json`. Use the empty prefix and match
the exact path instead: `findResources("", id -> id.getPath().equals("opb82_rules.json"))`.
Symptom was "Loaded 0 articles" with no error. Instrument with a debug dump of
`findResources("", p->p.getPath().endsWith(".json")).keySet()` to see the real namespace/paths.

## Duplicate-class mess
`src/main/java/com/ben/csp/…` had root-vs-subpackage duplicate classes. Resolution rule
used: a class is LIVE iff some other file resolves to it via an explicit
`import pkg.Simple;` or a same-package reference or a wildcard `import pkg.*;`. Removed 21
dead ones (git preserves them). After deleting any class, ALWAYS recompile — the repo
compiles every source set, so an accidental live deletion shows up immediately.

## Item registration / creative tab
`ModItems` originally registered items via a local `register(...)` helper with no public
Item fields, so nothing could reference them. Rewrote it to expose `public static final
Item` fields and take `Item.Settings` in each item ctor. The lang file advertised
`itemGroup.csp-modern` but NO ItemGroup existed → blocks/items were in no creative tab.
Added `ModItemGroups` (FabricItemGroup.builder) and registered it after blocks+items.
